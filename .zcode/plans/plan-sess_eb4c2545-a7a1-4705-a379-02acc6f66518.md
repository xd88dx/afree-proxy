# 使用痕迹落盘分离：`*-config.json` 恢复"仅用户操作才变"

## Context

外部监测 afree 配置变化时，token 用量、最近使用时间、冷却状态等使用痕迹与配置混在同一批 JSON 文件里高频变化（cline 2s flusher 每请求写、zen/trae 429 即时写、proxy health 60s 写），无法精准抓取配置变更。本计划将全部使用痕迹拆到独立的 `*-usage.json`，配置文件恢复"只有面板操作/备份导入/凭据轮转才写"的性质。WorkBuddy 子系统已是此格局，本次把单平台系列（cline/zen/trae/amd/or/th/other）对齐，proxy health 恢复独立文件（旧先例 `.proxy-health.json`）。

已确认决策：**一次全拆 7 域 + health**；**系统自学习低频回写留配置文件**（Q2 拍板：zen ModelAliases/Endpoints、clineStreamRequired、other Models.Fetched、egress Since、订阅 cron 整池替换）；**凭据轮转留配置**（时间戳扫尾新增结论：trae 续期回写 Token/RefreshToken/ExpiredAt [client.go:2068-2076]、zen Sessions 时间戳 [zen_session.go:41-55]、wb auths 回写——凭据本体语义属配置）。

## 拆分明细（按域）

### 1. cline（改动最大）→ `cline-usage.json`
- `internal/app/types.go`：`Account` 删除 Status/LastUsed/UsageCount/UsageCountToday/UsageDate/TokensTotal/TokensToday/TokensDate/CooldownUntil/LastReason；保留 AccountID/Email/Nickname/RefreshToken/APIToken/ProxyMain/ProxyBackup/PoolEnabled。`EgressProxy/NoEgress` 是 egress 推导的展示投影，改为 `json:"-"` 不再落盘（展示时实时回填）。`AccountPool.CurrentIdx` 移入 usage 文件顶层。
- 新 `AccountUsage` struct（含上列痕迹字段）+ 文件 struct `{currentIdx, accounts: map[AccountID]*AccountUsage}`。
- `pool.go`：包级 `poolUsage` 表（poolMu 保护）；痕迹写入改走独立 `savePoolUsage`（沿用 poolSaveMu 串行 + tmp/rename）；`startPoolFlusher` 2s flush 只写 usage 文件；显式保存点（昵称/启停/排序/导入等）只写 config 文件。
- 读写点改造（删字段后编译错误即清单，模式 = `usageFor(id)` 锁内查表）：`pool.go` bumpUsage/recordAccountTokens/markAccountCooldown/pickAccount(Excluding)/doRefreshAccountToken/ListAccounts 的解冻+跨日重置副作用/resetTodayUsage；`proxy.go` 429/401 判死/记账（~1340-1396）；`admin.go` Test（~789/912/940）。
- `ListAccounts` 面板输出改为合成视图 struct，**JSON 字段名逐字保持**（前端零改动的前提）。

### 2. zen → `zen-usage.json`
- `zen.go` zenConfigData 删 Cool/KeyTokens（真身 zenKeyCool/zenKeyTokens 包级变量不动）；新文件 `{cool, keyTokens}`；`zenTokensFlush` 的 save 与 `cooldownZenKey` 即时落盘目标改为 `saveZenUsage`（新 zenUsageMu + tmp/rename）；load 时双向同步真身。
- **留在 zen-config.json**（时间戳扫尾明确）：`Sessions`（会话令牌凭据 + Updated/CreatedAt/RefreshedAt，403 换新时变，低频）、`ModelAliases`（含 Since）、`Endpoints`。

### 3. trae → `trae-usage.json`
- `internal/trae/config.go`：`Account` 删 Tokens/Credits/Checkin/CheckinDeviceGen，`Config` 删 Cool；新文件 `{cool, accounts: map[账号ID]{tokens, credits, checkin, checkinDeviceGen}}`。
- **留在 trae-config.json**（凭据）：`Token`/`RefreshToken`/`ExpiredAt`——续期成功后即时 save() 回写（client.go:2068-2076），天级低频，语义为凭据轮转。
- 读写点：`trae/pool.go` RecordAccountTokens/Cooldown/Uncool、`trae/client.go` FetchCredits 落盘（~2160）、`trae/checkin.go` recordCheckin/9074 换设备、`app/trae.go` 后台额度刷新与面板；账号列/状态列合成输出。

### 4. amd/or/th/other（四家同构，一个模式复制）→ `<p>-usage.json`
- 各 `config.go`：`Config` 删 KeyTokens/Cool；新文件 `{keyTokens, cool}`（键 = key 明文）；`tokensFlush` DirtyFlusher 的 save 指向 `saveUsage`；`Cooldown`/`Uncool` 即时落盘改写 usage 文件；`RecordKeyTokens` 改查 usage 表；面板 KeyStatus 输出 JSON 字段不变。

### 5. proxy health → `proxy-health.json`
- `proxy_config.go`：proxyConfigFileData 删 Health/HealthSavedAt；`proxy_health.go` flushProxyHealth 改直接原子写新文件（60s 合批不变），load 从新文件读；代理变动清零逻辑不动。proxy-config.json 写点收敛为纯用户操作 + egress/订阅（属"留配置"决策范围）。

## 配套必做

1. **一次性迁移**（每域）：load 时若 usage 文件不存在且 config 含痕迹键，用 legacy shim struct（仅痕迹字段、json tag 与旧一致）提取 → 写 usage 文件；幂等（usage 文件存在即跳过）。**必做**：否则升级丢冷却，违背 2026-10-28 冷却落盘决策。
2. **备份导出/导入**（`admin_backup.go`）：导出核对接不含痕迹（拆分后自然更干净）；导入按新账号/key 集合清理 usage 孤儿条目。
3. **清空数据**（`admin_data.go`）：连各 `*-usage.json` 一起删。
4. **坏文件防护**：新 usage 文件 load 失败改名 `.corrupt-<时间戳>` 留档（同现有 config 模式）。
5. **文件名注册**：`kit.ResolveDataPath` 新增 8 个文件名常量，命名风格（点前缀）对齐现有 config 常量。
6. **锁序不变**：子系统锁在外、文件锁在内；原子写沿用 tmp+rename。

## 拆分后的文件分类（外部监测口径）

- **配置监测集合**（拆后仅在面板操作/备份导入/凭据轮转/低频自学习时变）：`cline-config.json`、`afree-config.json`、`proxy-config.json`、`zen-config.json`、`oprt/tkhb/amd/other/trae-config.json`、`workbuddy/config.json`、`workbuddy/auths/*.json`
- **痕迹文件**（随请求/后台任务变，不监测）：7 个 `*-usage.json`、`proxy-health.json`、`workbuddy/state.json`、`workbuddy/usage.json`、`workbuddy/request-logs/`、`workbuddy/balance_history.json`、`workbuddy/output_probes.json`、`workbuddy/model.json`、`requests.jsonl`、各日志文件

## 实施顺序

kit 层 → proxy health（最独立）→ key 池四家（同构）→ zen → trae → cline（读写点最多）→ 备份/清空/迁移收尾。每步 `go build ./...` 兜底漏改点。

## 验证

- `go build ./... && go vet ./...` 全绿；`go test ./... -count=1` 无新增失败。
- 本机 afree 测试容器（3457）端到端：发真实请求 → `*-config.json` 哈希不变、`*-usage.json` 变化（外部监测口径演示）；重启后冷却/token 计数保留（迁移验证）；面板账号列/key 状态/代理健康各页显示正常（zh 模式截图自测，UI 铁律）；备份导出→导入→清空数据回归。
- UI 改动按惯例浏览器自测后交付；不提交，等用户验收指示。
